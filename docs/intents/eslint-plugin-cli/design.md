# Design — `eslint-plugin-cli`

Intent: [`intent.md`](./intent.md). **Status:** draft.

---

## Requirements

- **R1** Package layout mirrors an eslint-repo plugin: `src/index.ts` (plugin object
  with `rules`, `configs.recommended`, `configs.strict`), `src/rules/<rule>.ts`,
  `src/rules/__tests__/<rule>.test.ts` (RuleTester, valid/invalid per host),
  `docs/rules/<rule>.md`, `README.md` with the rule table generated by a script, and a
  `package.json` whose `main`/`exports` point at built `dist/` with a lock that the
  build produces them.
- **R2** Host detection helpers in `src/lib/hosts.ts`: `isCommanderAction(node)`,
  `isYargsHandler(node)`, `isCommandDefinition(node)`, `optionNameOf(node)`, shared by
  every rule and tested on their own.
- **R3** Each rule's message uses `formatLLMMessage` from the devkit with `issueName`,
  `description`, `severity`, `fix`, `documentationLink` pointing at the docs site.
- **R4** `recommended` enables all rules at `error`; `strict` additionally turns
  `no-prompt-without-flag` on (it starts as opt-in until its precision is proven).
- **R5** Fixtures: `examples/demo-cli-commander` and `examples/demo-cli-yargs` are linted
  in the package's test as integration cases — the layered demo must be clean, an
  un-layered copy under `__fixtures__/` must produce exactly the expected findings.

## Design

Rule by rule, the AST anchor and the precision guard:

| Rule | Anchor | Guard |
| :-- | :-- | :-- |
| `require-json-output` | `CallExpression` `.command(` on a commander/yargs receiver | skip when the program is wrapped by `withAgentLayer` / `withAgentMiddleware` anywhere in the file |
| `no-console-in-command` | `console.*` whose enclosing function is an `isCommanderAction` / `isYargsHandler` | only direct enclosing function; helpers called from handlers are not reported |
| `prefer-native-style-text` | `ImportDeclaration` / `require` of the listed packages | none needed; report with the `util.styleText` replacement |
| `exit-code-constant` | numeric literal argument to `process.exit`, assignment to `process.exitCode`, `exitOverride` callbacks | allow `0` |
| `no-process-exit-in-handler` | `process.exit` inside a handler | same enclosing-function test as above |
| `no-help-on-runtime-error` | `showHelpAfterError(true)` or a string, `showHelpOnFail(true)`, `.help()`/`.outputHelp()` inside `CatchClause` | report only literal `true`/string arguments |
| `require-command-example` | `.command(` without a sibling `.addHelpText('after'` / `.example(` in the same chain | chains only; commands assigned to variables are traced one hop |
| `env-option-documented` | `.option(` whose default/coerce argument references `process.env.X` without `.env(` in the chain | commander `Option#env`, yargs `.env()` at root counts as documented |
| `no-reserved-option-names` | `.option('--name'…)` / `.option('name'…)` in the reserved set | none |
| `no-prompt-without-flag` | prompt-library call whose enclosing handler does not reference `options.<same identifier>` first | `strict` only until measured |
| `deprecated-requires-replacement` | `.deprecated` / `{ deprecated: true }` without a string containing "use " or a `replacement` key | none |

Everything lives in this repo; only the `cli` preset is added to `eslint-config-interlace`
upstream, depending on the published package.

## Verification

- RuleTester suites, 100% branch coverage, in the root `npm test`.
- Integration: the demo CLIs as fixtures (R5).
- First-run report on `interlace-ui` and `eslint/scripts/*.ts` attached to the PR.
- The eslint repo's `PRE_PUBLISH_INTEGRITY_GATE.md` checks run in this repo's
  `release.yml` for this package: `main` resolves in the built `dist/`.

## Rejected alternatives

- **Living in the eslint monorepo.** Decided in the umbrella: fixtures are this repo's
  demo CLIs and rules change with the runtime.
- **Type-aware rules.** Would double the setup cost for consumers and most CLI repos
  are plain JS; name-based anchors with precision guards are enough for these idioms.
- **One mega-rule "cli/floor".** Consumers need to disable one requirement at a time
  with a reason, exactly as this repo does.

## Out of scope

- Autofixes beyond `prefer-native-style-text` and `exit-code-constant` (the rest change
  behaviour, not text).
- citty, oclif or cac idioms.
- A "did you mean" for reserved names — the runtime layer does that at run time.
