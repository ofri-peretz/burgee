A native program can name the command that runs when argv names none. Mark one command `default: true` and `tool` runs it, and so does `tool --port 8080` with only that command's options. A word goes to it as its positional when it declares one and the word is not near a command's name, so `tool public` serves `public` and `tool buid` is still refused with `did you mean build?`. This works at every level: `tool remote` runs `remote`'s default. Two defaults at one level are refused when `defineProgram` builds the program, and the refusal names both. Help lists the default with `(default)`, its usage reads `[command]`, and it shows the default's arguments, options and examples under the level's own, which is what yargs issue 1331 asks of yargs. `--schema` carries `default: true` on the command, and the completion scripts offer the default's options at its parent. `--mcp` is unchanged, because the default is already a tool. This is commander's `isDefault` and yargs' `$0` for the native API. The façades dispatch their incumbents' defaults as before.
