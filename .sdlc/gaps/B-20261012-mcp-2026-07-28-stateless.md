`--mcp` negotiates the two handshake revisions, `2025-06-18` and `2025-11-25`, and answers a
client asking for anything else with `2025-11-25`
([D-20261012-mcp-version-negotiation](../decisions/D-20261012-mcp-version-negotiation.md)). The
newest published revision, `2026-07-28`, is not served. It removes `initialize`: every request
carries its protocol version and client capabilities in `_meta`, the server must implement
`server/discover`, every result carries `resultType`, list results carry `ttlMs` and
`cacheScope`, and `ping` is gone (`docs/specification/2026-07-28/changelog.mdx` in the
specification repository at `1f520964b2`).

A dual-era client still works with this server today: on stdio it probes with
`server/discover`, receives `method not found`, and falls back to `initialize`. A client that
speaks only `2026-07-28` does not: it never sends `initialize`, and its requests reach a server
that has not read their `_meta`. Serving that era is a second dispatch path in `mcp.ts` and a
third vendored schema, which is a design of its own and a byte cost on `./mcp` that this
intent's budget decision does not cover.
