**`burgee/yargs` is graded at yargs 18.2.0: 816 / 816, level with (two above) the control's 814 / 816; the `burgee/yargs` bundle ceiling stays at 108,420 B, and the fish support 18.2.0 added is paid for inside it.** Re-vendored with `npx tsx scripts/vendor-suite.ts yargs --version 18.2.0` (tag `v18.2.0`, commit `e49b60aa`): one file changed, `test/completion.mjs`, which gains a `fish` block of twelve cases (the vendor step counts +2 because ten reuse the zsh block's titles). Against the new suite `burgee/yargs` scored 806 / 816 — the ten fish cases whose candidates carry a description — and the control 814 / 816, its two long-documented version-lookup failures (`hosts.ts` `controlFailures`). The package diff between 18.1.0 and 18.2.0 is `completion.js` and `completion-templates.js` only: fish is detected from `SHELL`, a candidate is `value<TAB>description` with nothing escaped, choices are offered verbatim, the script is `completionFishTemplate`; and the zsh script's `zsh_eval_context` test lost a stray `'` that made it never match. `burgee/yargs/completion.ts` follows both, and the pre-existing difference is kept on purpose: under zsh and bash burgee escapes `\` as well as `:` (#23–#26), and fish, like upstream, escapes nothing.

**The bytes.** The port as upstream writes it measured 108,785 B against the 108,420 ceiling (+483). Raising a ceiling because the incumbent grew is a loosening and the owner's call, so it was not raised: the three script templates repeat the same header, footer, function name and completion command, and writing each once (`head`, `foot`, `fn`, `ask`) brings the façade to 108,299 B locally — three bytes under main's 108,302 with fish in it. The scripts produced are unchanged byte for byte, and `packages/burgee/src/yargs/completion-templates.test.ts` now holds all three to the installed yargs's own templates, plus the fish candidates and scripts against real yargs; each of its assertions was run against eleven source mutations and every mutation went red. The root and `benchmarks/` ranges move to `^18.2.0` (the lockfile resolves 18.2.0, hand-applied so the Linux lock shape is kept); `GRADED_VERSIONS.yargs`, the baseline, `competitors.json`'s fingerprint (367,071 B), the capability cell (yargs now completes bash, zsh and fish; PowerShell is what it lacks) and every page that stated 804 follow. `SUPPORTED_MAJORS` does not move: 18.2.0 is the same major. The `yargs-compat` spec's X2 (804 tests, 18.1.0) records the state when it was accepted and is superseded by this regrade rather than rewritten.
