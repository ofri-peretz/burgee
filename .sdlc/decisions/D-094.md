**Owner — `RELEASE_BOT_PAT` is the only real fix, and it is a secret only you can set.** A PR opened with `GITHUB_TOKEN` raises no workflow runs, so it sits at 0 checks against 3 required ones. This has now blocked **#299, #367, #383 and #393**, each needing a manual close-and-reopen; one release took four attempts. The workflow's own comment claimed the default token "keeps this workflow working until the secret is added" — it is exactly the token that does not, and that sentence is corrected. Default until the secret exists: **unblock by hand, update-branch before reopening, and wait for the run to settle** — a reopen cancels anything in flight and the Quality Gate then fails in four seconds on `cancelled` sub-jobs rather than on anything real.
