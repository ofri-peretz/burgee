**On stdout, alone, on every front end, with the exit code the error names; stderr stays empty under `--json`.** O1 promises one envelope for `--json`, and both façades already wrote their failure envelope to stdout; the engine alone wrote it to stderr with stdout empty, so a caller reading stdout for the envelope read nothing on exactly the failing runs, and `--mcp` only found it through a fallback. The earlier reading (*an error must never be mixed into stdout*) does not survive `ok: false`, which is what stops a failure being read as a result. The façades gain the same guarantee on the path every commander and yargs program actually takes, nothing injected: a throw, a rejection or a thrown non-Error under `--json` is the envelope plus `process.exitCode`, never a stack, and without `--json` stays the incumbent's own. `AuthError` exits 5 and `UsageError` 2 on the façades too, as E6 already said; the façade envelope keeps its string `code` space (`runtime`, `auth`, `usage`), per `facade-gets-more`. No `name` field and no stack, and no debug flag added for one.
