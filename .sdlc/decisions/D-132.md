**Yes, all nine: `engines.node` is `^20.19.0` or `>=22.13.0`; compat-oracle and the workspace stay on 24.** Evidence: a static scan of every `packages/*/src` for post-20 APIs found one: `Promise.withResolvers` (Node 22) in `caique/src/inquirer.ts`, now the executor form, so there is no polyfill and no dependency. Everything else is 20-safe: `toSorted`/`toReversed` (20), `util.styleText` with an array and `validateStream` (probed on 20.19.0), `import.meta.resolve` (20.6), recursive `readdirSync` (20.1), `parseArgs` tokens, and JSON import attributes (they load without a warning on 20.19). Every suite passed locally on 20.19.0, 22.12.0 and 22.13.0. Two burgee timing tests failed once on 22.12 at load ~120 and passed on rerun. The floor is set by K2 rather than by the code. `require(esm)` is unflagged from 20.19 and 22.12, but 22.12 prints an ExperimentalWarning, even for an ESM importer of `closeout/signal-exit`'s `.cjs`, and 22.13 does not. So 22.13 is the floor. All nine share one range so that no dependant admits a Node its dependency refuses. The new `floor` job in `compat.yml` runs each published suite on exactly 20.19.0 and 22.13.0 × three OSes. `package-shape-lock.test.ts` fails when `engines`, that matrix or a README Node badge disagree. A caique test now runs a prompt end to end, because no package suite ran `createPrompt` before. It fails on 20.19 without the fix. Released as **minor**: widening support breaks no one, but it is a support-matrix change a reader should see in the version, and in 0.x the minor is that slot. Support is claimed only once the PR's `floor` cells are green
