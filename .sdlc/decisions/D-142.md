**The name carries the machine class, and the bands read CI runs only.** `<date>-<sha>.json` named a commit, not a run: on 2026-09-22 a local `npm run bench` of `c0fa8a3` (M4 Pro, `ci: false`) landed in #420 at the path the nightly's run of the same commit (four-core EPYC, `ci: true`) needed, so #419 could only land by deleting it and was closed. Observations are now `<date>-<sha>-ci.json` or `<date>-<sha>-local.json`, derived from `machine.ci` in `resultsName` rather than asserted by a caller; `bench.yml`'s rename step expects the `-ci` form; #419's two files are recovered from its branch as `2026-09-22-c0fa8a3-ci.json`; the eleven local observations already committed in each suite — including `7c4db40`, landed by #428 the same afternoon — are renamed `-local`, and the 107 older CI ones in each keep their unsuffixed names because renaming them would make `--backfill-git` find every point twice under two keys. `published.test.ts` fails if a CI and a local name ever coincide or if a committed name disagrees with its own document, and failed on the old naming with all four cases before the fix. **The bands read `machine.ci === true` only**, from the document so the unsuffixed and the published files are sorted by the same rule. A series mixing an M4 Pro and a four-core runner is not one series: `cold-start-ratio` measured σ 0.014 around 1.076 over 109 CI runs and 1.303 over four local ones, every local point more than ten CI σ out — one laptop run would breach on its own, or several would widen σ until a real drift fits inside. The deterministic bands lose nothing: CI measures every one on every push to main. The CI class is itself several CPU models (EPYC 7763, 9V74, Xeon), which is `ubuntu-latest`'s four-vCPU runner class and is what the existing σ already absorbs. `control-bands.history.json` needed no purge: its newest point is 2026-09-15 and the first local observation is 2026-09-21. Local observations keep landing — data for a person, not for a σ
