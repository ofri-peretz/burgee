**`controlroom/ink` is ink 6.8's API on React's own reconciler, laid out by a TypeScript port of yoga's algorithm, writing ink's byte protocol from one file of its own.** Graded 2026-10-05 on darwin through `compat-oracle`: **ink 576 / 584** (593 vendored, 9 colour cases excluded with their reasons below, 8 kitty-protocol cases failing), **`@inkjs/ui` 103 / 103** through the `'ink'` alias, with its React 18 and `react-reconciler` 0.29. Control 584 / 584 and 103 / 103.

**1. React: the program's, through its own reconciler, both lines.** `react` and `react-reconciler` are optional peers (`peerDependenciesMeta`), loaded in `ink/react.ts` with `import()` under top-level await, so a missing one is an `InkPeerError` with `code: 'E_PEER_MISSING'` and a `fix` naming `npm install react react-reconciler`, not a resolver error. ink itself has top-level await, so `require('ink')` already fails and nothing a caller could do changes. One host config serves `react-reconciler` 0.29 (React 18: `prepareUpdate`, a payload argument, `getCurrentEventPriority`) and 0.31+ (React 19: `commitUpdate(instance, type, …)`, the three priority hooks, `updateContainerSync`/`flushSyncWork`); ink's row grades the second line and `@inkjs/ui`'s the first. A lock in `scripts/package-shape-lock.test.ts` admits the two as the one exception D-111 now has: named per package, and only as optional peers, which npm never installs.

**2. Writing: ink's protocol, in one file, with the family's sequences.** R15 says every frame goes through flagstaff's `frameWriter`. ink's suite grades bytes *and* write calls: `debug` mode writes each frame whole and nothing else, a synchronized update is its own `write('\u001B[?2026h')` call, a frame is `eraseLines(previous) + frame` in one call, and `render.tsx` counts the writes. `frameWriter` diffs rows inside one synchronized block — correct for a frame flagstaff owns, and a different byte stream. Painting through it failed every `debug`-mode case. So the drop-in has its own boundary, as the core has `runtime.ts`: `ink/terminal.ts` is the one file under `src/ink/` that writes, and every sequence it writes is the family's (`paratext/csi`'s erase and cursor moves, `closeout/cursor`'s show and hide, `closeout/restore-cursor`). `src/boundary.test.ts` now walks `src/` recursively and names each boundary and the part of the rule it is exempt from; every other drop-in file is held to the whole rule, and the walk found two offences on its first run (a `.write(` that was the output grid's own method, now `draw`, and a spelled `CSI Z` the Tab handler now decodes through the key parser). The SGR the output grid re-emits is roundel's (`roundel/tokens`' painter) and OSC 8 is paratext's record, so controlroom still spells no escape sequence (constraint 5).

**3. CI: ink's rule, not roundel's mode.** ink takes its CI path (static output as it arrives, the last frame once) on is-in-ci's rule: `CI`, `CONTINUOUS_INTEGRATION` or any `CI_*` present, `CI=0` and `CI=false` not CI, a terminal or not. roundel's `outputMode` is `ci` for a pipe whose `CI` is set — `false` included — and the suite runs under `CI=false` on a pipe, so routing through roundel sent all 593 cases down the CI path. Constraint 1 says the suite decides; `ink/process.ts` keeps ink's rule, and `scripts/inline-implementation-lock.test.ts` records it in `KNOWN` with that reason (the sixteenth entry, at the ceiling). roundel's policy is read for the one thing ink has no opinion on: `CLI_ACCESSIBLE` turns screen-reader output on by default, beside ink's own `INK_SCREEN_READER`.

**4. Layout: yoga 3's algorithm, for the props ink sets.** `ink/flex.ts` reproduces `CalculateLayout.cpp` for ink's `Box` props: flex basis, lines and wrapping, the two free-space passes, justification (all six), cross and multi-line alignment, gap, percentages, `display: none`, the absolute children `<Static>` is, and yoga's pixel-grid rounding — absolute edges rounded and a measured (text) node's left edge floored, which is why ink's own `space-around` case is `test.failing` and why the subset fails it the same way. Not reproduced, because ink sets none of them: `aspectRatio`, `maxWidth`/`maxHeight`, inset offsets, auto margins, baseline alignment, `overflow: scroll`, RTL. No case of either suite depends on one, so no case is excluded for layout.

**5. What the oracle needed.** `Host.peers`: on a target run, a resolve hook (the alias hook's file, extended) sends a peer the target imports to the suite's copy, so the target and the suite share one React — two Reacts break every hook, which the ink-suite decision left for this phase. `Host.targetInternals`: `render.tsx` imports `bsu`/`esu` and `kitty-keyboard.tsx` imports `parseKeypress` from ink's internal paths; on a target run those paths now re-export the drop-in's own modules of the same job (`dist/ink/terminal.js`, `dist/ink/keypress.js`), as the control links ink's `build/` files. Without it both files died at link time and 104 cases measured nothing. Neither changes a control run. `grade.test.ts` drives the peer hook in a real child, and it was red with the redirect removed.

**6. The nine excluded cases: colour that depends on the runner.** `background.tsx` sets `chalk.level = 3` on the suite's own chalk singleton before each case, and ink colours through that same module; the drop-in colours through roundel, whose level is the environment's, so under `FORCE_COLOR=true` the seven truecolor and 256-colour background cases pass on GitHub Actions (level 3) and fail on a laptop (level 1). The two `ansi256` text cases are a chalk major: ink's chalk 5 emits `ansi256()` unchanged at level 1, and roundel follows chalk 6, which downsamples it. Each is an `excludes` entry with that reason, so both runners publish one number; every other colour case is graded.

**7. Not built: kitty keyboard negotiation (8 failing cases).** The drop-in decodes the kitty protocol's keys (the other 68 cases of `kitty-keyboard.tsx` pass, its `parseKeypress` cases among them) but does not push, pop or query the protocol: `CSI > flags u`, `CSI < u` and `CSI ? u` have no home in the family yet, and spelling them here would break constraint 5. Their home is `caique/keys`, which owns raw mode and key input for a screen. The eight cases stay failing, not excluded, until then.

**8. Coverage.** `src/ink/` is graded by 687 cases in another process, as the other façades are; its own vitest file pins only what those suites cannot (the surface is ink's and no more, the peer refusal, and three yoga behaviours). controlroom's vitest config sets no coverage thresholds today, before or after this change.
