**Yes to both, as R19–R22 in `.sdlc/intents/controlroom/spec.md`; D-158's cap of ten stands.** Claude Code is written for Ink and runs inline, so the shape needs what the full-screen spec lacked. **R19, inline screens:** `screen: 'inline'`, the default as in Ink, with a live region repainted through flagstaff's seam and a committed region that flows into scrollback once (Ink's `<Static>`); R4's alternate screen becomes `screen: 'alternate'`. **R20, an input line:** caique's line editor as a component hosted in the live region (multi-line, history, bracketed paste, a program-fed completion menu for `/commands` and `@files`); the editor stays caique's, and the intent's "text editing inside a pane" stays out apart from this. **R21, chat widgets:** flagstaff `markdown` (streamed, committed per block) and `diff`, each with a static projection; syntax highlighting is out of scope. **R22, boilerplates:** `examples/chat-cli` (native API), `examples/chat-cli-ink` (the same app on `controlroom/ink`, R17's whole-app proof) and `examples/dashboard` (the intent's reference demo), each a CI job under a PTY and under `pipe`/`--json`, plus a docs page "Start from a boilerplate". No `create-*` package: it would be the eleventh, so boilerplates are copied from `examples/` until that is measured to be the friction. v1 now waits on all three boilerplates
