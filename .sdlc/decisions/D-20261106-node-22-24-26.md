**Decided.** Every published package declares `engines.node: ">=22.13.0"`, released as a **major**
on all eleven: dropping a Node line breaks a consumer still on it, whatever the code does. CI
grades three versions:

- **24**, the `.nvmrc` Node: `compat.yml`'s `matrix` job, unchanged — three cells, required on
  every pull request. A pull request costs no more than before.
- **22.13.0 and 26**: `compat.yml`'s `floor` job, the published suites on the three OSes, nightly,
  on a dispatch and on a `run-full-ci` pull request — the trigger the 20.19.0/22.13.0 floor had.
  22.13.0 is exact, because a floor is only a claim if the floor itself is what runs.

**Why.** Node 18 reached end-of-life on 2025-04-30 and Node 20 on 2026-04-30; Node 26 was promoted
to Active LTS in October 2026. D-20261020-node-26-waits-for-lts held 26 back until that promotion;
it has happened, so 26 is graded again. It runs in `floor` rather than as a fourth `matrix` cell
per OS, so the required pull-request checks stay at three.

**Why 22.13 and not 22.0.** K2's reason from D-132 holds: 22.12 loads `require(esm)` but prints an
ExperimentalWarning, even for an ESM importer of `closeout/signal-exit`'s `.cjs`; 22.13 does not.

**What follows from it.**

- `scripts/package-shape-lock.test.ts` holds `NODE_FLOOR = '>=22.13.0'`, and requires `floor`'s
  matrix to be `['22.13.0', '26']` and every README Node badge to say `22.13+`.
- `burgee migrate`'s `floor` row (migrate-preflight R4) warns below 22.13.0 rather than 20.19.0,
  and its fix is `npm pkg set "engines.node=>=22.13.0"`. An ES-module project on `>=22` now gets
  that warning. `require-esm` (R3) is a fact about Node and is unchanged.
- Code written to keep Node 20 working (the executor form of `Promise.withResolvers` in caique,
  `with: { type: 'json' }` notes) stays: it is correct on 22 too, and no test shows it dead.
- oxmutate's `quiescence.test.ts` deadlock cases need `process.threadCpuUsage` (Node 23.9) and are
  red on the 22.13.0 cells today, as they were before this change; a separate change makes them
  skip below 23.9. 22 stays in the matrix so that skip keeps being exercised.

**Supersedes** D-132 (the `^20.19.0 || >=22.13.0` floor) and D-20261020-node-26-waits-for-lts.
