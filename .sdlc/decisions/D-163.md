**Three pairings of one shape, and only what closeout turned on is undone.** (1) `alternateScreen(stream, closeout?)` and `rawMode(input, closeout?)` sit beside `hideCursor(stream)`: each makes the change and registers its undo in the `restore` phase in the same call, returns the undo, runs it at most once whoever asks first, and unregisters on an early call — the pairing `interactive-screens/intent.md` asks for, so a screen package never writes its own restore. They are **root functions taking an optional instance, not methods on `install()`'s object**: the first build made them methods, a bundler keeps a method for every caller of `install()`, and burgee's core — which never enters a screen — grew 24,216 → 24,791 bundled bytes, over its 24,282 ceiling and past the cac ratio. As free functions they tree-shake; `hideCursor` keeps its own inline once-flag rather than the shared `paired()` helper for the same reason (30 B). What every `install()` caller does pay is point (3): +46 B, burgee 24,262. The leaves in `closeout/cursor` take the registrar as a second argument, as `hideCursor` already did. (2) `rawMode` turns raw mode off at exit **only if it turned it on**: an input whose `isRaw` is already true belongs to a prompt library or the program, and switching it off at exit would take the keyboard from its owner, so the call changes nothing and registers nothing; a non-TTY input, or one without `setRawMode`, likewise. Escapes are never written to a non-TTY stream, in either direction. No reference counting across two pairings on one stream — each pairing is its own undo, as `hideCursor`'s always was. (3) **A defect the spawned test found:** a real process whose shutdown was parked on a `flush` handler that holds nothing in the loop left through `'exit'` before the deadline (the deadline timer is `unref`'d), and `runSync` treated that as a second trigger and did nothing, so `restore` was never invoked and the terminal stayed broken. `run` and `runSync` now share one cursor over `PHASES`: on `'exit'` every phase not yet invoked is invoked synchronously, each still once. How that process *leaves* — it exits 0 rather than dying of the signal it received — is R1/R10's question and is recorded open in `closeout/spec.md`, not pinned by a test. Also rejected: asserting raw mode through a real PTY, because node resets its own stdio's TTY mode as it exits, so such a test passes on a closeout that never turns raw mode off
