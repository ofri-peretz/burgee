**The owner, 2026-09-27: each becomes "something acceptable and realistic, while we consistently keep them as low as we can" — a downward-only ratchet.** A ceiling just above today's measurement, met today; the benchmark gate fails the moment the measurement exceeds it; it may be lowered by anyone and raised only by a newer D-row cited in its history; and when a measurement lands comfortably below, it comes down. The three ceilings, in `.sdlc/bands/claim-ratchets.json`, each with its derivation: **`lighter-than-cac` 2.35** — deterministic, so the build on main after #631: 24,216 / 10,452 B = 2.317; CI builds ~32 B heavier than local, so 80 B go on our side (24,296 / 10,452 = 2.324) and it rounds up to the next 0.05. **`lighter-than-commander` 1.565** — 60,969 / 39,084 B = 1.560, with 80 B 1.562, rounded up to 0.005, the step this row's B4 ceiling has always moved in: exactly the J3/J4 ceiling it already had, carried over. The next 0.05 (1.6) would have been a raise wearing a first ceiling's clothes. **`cold-start-at-or-below-cac` 1.6** — noisy, so from CI's own spread: the last N = 26 CI observations in `benchmarks/results/cli-benchmarks/*-ci.json` (c0fa8a3 on 2026-09-22 to 7b694f7 on 2026-09-27), mean 1.490, sd 0.034, p95 1.540, max 1.553; the larger of mean + 3 sd (1.590) and the max, rounded up to 0.05. The p95 rule alone gives 1.55, which c938fbf's 1.553 exceeds: one red run in 26 for nothing. Newest CI 1.512. **One number, three readers**: `benchmarks/claim-ratchets.ts` feeds the claim's `test.max` in `claims.ts`, B4's ratio gate (`burgee` is the lower of the wave-5 budget 2.9 and the ratchet, so the budget stays the release's outer limit; `burgee/commander` is the ratchet) and B2's `burgee` gate (1.7 before). **Downward-only, enforced** by `scripts/claim-ratchets-lock.test.ts`: the ceiling must be its history's last step, a step up must cite a newer D-row that exists here, history is append-only against `git show HEAD:` (the `release-budget-lock` approach), the claim reads the same ceiling, and the README row states it; `benchmarks/ratchet.test.ts` proves each gate fires one step over. **The ✅ is CI's**: `claim-table-lock.test.ts` now reads, for each met row, the newest CI observation or promoted document that measures it (never a `-local.json`), and holds that document to the same fourteen days — D-150's rule made literal, and needed now that a perf row can be ✅: a laptop's `--axis weight` run landing newest would otherwise have failed the cold-start row it never measured, and a laptop's cold start is not what 1.6 was derived from. **Keeping them low**: `npm run ratchets:propose` prints the ceiling each `derive` rule gives from the latest measurement and says LOWER when it is below the current one. **Wording**: the claim text and the README rows say what is gated ("stays within 2.35× of `cac` alone … ratchet; lowered as it shrinks"); the ids are kept, because every results document and D-row keys them.
