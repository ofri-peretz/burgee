**All three controls were the harness, and all three now pass: boxen 9.0.0 213 / 213, dotenv 18.0.5 179 / 179 (one case skips itself off win32), clack 1.8.1 16 / 16. `flagstaff/boxen` is ported to boxen 9 and grades 213 / 213, level. `seniority` grades 128 / 179 against dotenv 18; its lane brings the rest.** Measured on darwin, Node 24.13.0, 2026-10-06. The bot's re-vendor (#794) read `boxen: nothing passed`, `dotenv: 52 failing`, `clack: 5 failing`; none of the three was a defect in the incumbent (rule 4: the control proves the gate, so it is fixed first).

**clack — the vendor step cloned the wrong commit.** `SAFE_REF` in `vendor.ts` refused any ref that does not open with a letter or digit, so every monorepo tag (`@clack/prompts@1.8.1`, `@inquirer/core@12.0.4`) was "unsafe", and the refusal fell into the same `catch` as a missing tag: the step cloned the default branch and recorded `tag: null`. clack's default branch was three commits past 1.8.1 with `spinner-accessible.test.ts` and its changesets unreleased, so 1.8.1 failed five cases of a suite it never shipped — and the `17 / 16` row was that seventh file over a reference of sixteen. `@inquirer/core`'s default branch happened to be 12.0.4, so its row was right by luck. The fix allows a leading `@` (git's option parser reads only `-`) and makes a refused ref an error rather than an untagged release. Re-vendored at the tag, clack's suite is byte-identical to main's and nothing about the row moves. `vendor-run.test.ts` holds both: a scoped tag clones the tag and not HEAD, and an option-shaped ref throws without calling git. Both were red against the unfixed code.

**boxen — the runner, the glob and a helper.** boxen 9 moved from ava to `node --test` with `.snapshot` files and renamed every file `*.test.js`. The host still said `runner: 'ava'` and `testGlob: '*.js'`, and every file opens with `import './setup.js'` — a side-effect import, no `from` — which the sibling walk did not see, so the helper that fixes `COLUMNS`, chalk's level and the snapshot path was never vendored. The host now says `node:test` and `*.test.js`, `SIBLING` reads a bare and a dynamic `import` (red first in `vendor-run.test.ts`), and the incumbent is a `suiteDeps` pin, because the workspace hoists boxen 8.0.1 and the suite's `chalk` has to be the instance boxen draws with. Control: 213 / 213.

**dotenv — the suite tests the build, and the pin was 17.** dotenv 18's suite spawns `node dist/index.cjs run …`, preloads `dist/config.cjs`, and runs programs that name `dotenv` and `dotenv/config` from the repo root; and `suiteDeps` still pinned `dotenv@17.4.2`, so the control graded 18's suite against 17. The harness change is the one written on `feat/seniority-dotenv-18` (63b80b238d) and adopted here unchanged: `Host.entries` (files the suite reaches by path, linked to the incumbent's own on the control, a generated CommonJS shim on a target run), `Host.selfExports` (the vendored root takes dotenv's name so self-reference reaches whichever is graded), a resolver anchored inside `node_modules` so that self-reference cannot answer the control's own lookup, the pins moved to 18.0.5 and tap 21.7.4, `.env.vault` swapped for `.env.bom`, and dotenv 17.4.2 kept as `dotenv-17` in `PREVIOUS_MAJORS`. Control 179 / 179. **seniority is graded, not changed, here:** 128 / 179 against 18, 106 / 141 against 17 — it still speaks 17, and the `seniority/dotenv/config` and `seniority/dotenv/cli` subpaths the entries point at are its lane's to build. `DROP_INS` is not given the `selfExports` pairs for the same reason: `migrate` must not rewrite to a subpath that does not exist yet.

**`flagstaff/boxen` follows boxen 9, not 8.** D-170 accepted it as a boxen 8 drop-in and put 9 out of scope; the 1.0 bar since is every drop-in at the incumbent's latest release. The port is boxen 9.0.0's `index.js` function for function, on `linegauge` (width, slice, widest, wrap) and `roundel/chalk`. Two of 8's answers changed and the façade takes 9's: a hex colour must be real hex (8's `[0-f]` range took `#GGG`), and `vertical` / `horizontal` are a fallback for `left` / `top` rather than an override. So `SUPPORTED_MAJORS.boxen` is `[9]` and boxen 8 is neither graded nor claimed; claiming it again needs 8's suite vendored as a previous major and graded level. `boxen.test.ts`'s two pins of 8's behaviour are restated to 9's, each from real boxen 9.0.0 output. **Weight:** the `./boxen` lock moves 12,634 → 17,600 and its budget 13,000 → 18,000 — boxen's own package doubled across the same release (10,923 → 22,037 B self). Across packages, by the method `competitors.json` uses for boxen, `flagstaff/boxen` is 67,748 B in three packages against boxen 9.0.0's 114,927 B in fourteen.

**The ten colour cases, and why the suite's `chalk` moves on a target run.** The port read 203 / 213 with the suite left alone. The ten were every case that does `chalk.level = 3` on the suite's own `chalk` and asserts a coloured box: boxen passes them because npm hands boxen and the program one chalk. `flagstaff/boxen` draws with `roundel/chalk`, so with the real chalk in the suite the cases grade which of two unrelated objects a level was written to. A migrated program does not have two: `burgee migrate` rewrites `chalk` to `roundel/chalk` beside `boxen` to `flagstaff/boxen`. `Host.migrated` says that per host — `{ chalk: 'roundel/chalk' }` on boxen — and a target run's resolve hook (the one `Host.alias` already loads) sends the suite's `chalk` to the drop-in; the control loads nothing. `scripts/migrate-drop-ins-lock.test.ts` refuses a `migrated` pair that is not a row of `DROP_INS`, so the field can only name a rewrite `migrate` really makes. Three cases in `grade.test.ts` hold the hook, one of them in a real child process, and all three were red against the unfixed `run.ts`. What this does not prove: a program that moves boxen and keeps chalk 6 gets an uncoloured box after `chalk.level = 3`, because the level is written to an object `flagstaff/boxen` never reads. That program is not one `migrate` leaves behind, and it is named here rather than hidden.

**One ratchet rose, and it is the owner's call.** `scripts/inline-implementation-lock.test.ts` caps the list of files that do a layer's job by hand at 16 and says it only goes down. The boxen 9 port matches ANSI escapes with a regex, which is linegauge's job by that lock's definition, because boxen 9's own `writeControls` decides which escapes a box keeps (an SGR, an OSC 8 hyperlink) and how a backspace crosses them, and its suite grades exactly that. linegauge exports no tokenizer that splits the way boxen splits. The two ways out were a new linegauge export, in a package at 1.0 and another lane's, or one more `KNOWN` entry with its reason; this takes the second and moves the ceiling to 17 with a comment naming this record. The way back down is that export. The same goes for the changeset: it is `minor`, on the reading that a drop-in follows its incumbent's current major; under strict semver the two answers boxen 9 changed (`#GGG` now throws, `vertical` no longer overrides `left`) make it a major of flagstaff, and that is also the owner's call.

**yargs 814 / 816 is not a regression.** The first block of #794's output is the control, and yargs' control carries a declared allowance of two (`controlFailures`: real yargs reads its version from the nearest `package.json`, which in the vendored copy is ours). `burgee/yargs` is 816 / 816 in both of #794's target blocks and in this run.
