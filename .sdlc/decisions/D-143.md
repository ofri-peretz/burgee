**One user prompt, with a tool loop capped at 8.** The design's "one turn" is the human's side: the agent gets one instruction and no second message, no clarification and no human reading `check`'s output for it. It never meant one model step — the prompt itself asks for four tool steps (read the schema, read the README, write the file, run `check`) and a repair when `check` refuses, so a cap of 3 measured the cap, not the schema. 8 is those four, one fix, one re-run, the final answer and one spare; it is a constant (`DEFAULT_MAX_TURNS` in `scripts/run-evals.ts`, `run-evals.test.ts` pins it and failed at 3), not tuned to a result, and `EVAL_MAX_TURNS` still overrides it. The eval is not re-run here: the only credential on this machine is the owner's employer Team login, and the stated rate is three consecutive **weekly** runs at 9 of 10, which is the CI job's to produce once `CLAUDE_CODE_OAUTH_TOKEN` exists (D-150).
