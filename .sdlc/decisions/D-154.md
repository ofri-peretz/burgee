**OIDC only; the token path is deleted, not switched.** It was already the only path in use: `NPM_TOKEN` exists in neither the repo nor any environment, runs 36093911201 and 36350488671 logged `NODE_AUTH_TOKEN:` empty, and every package's current version is published by *GitHub Actions* (`npm-oidc-no-reply@github.com`) with provenance from `release.yml`. A switch would guard a fallback that does not exist, and npm needs none: docs.npmjs.com/trusted-publishers — the CLI "uses them for authentication before falling back to traditional tokens", so a token never blocks OIDC; it only adds a second, silent, long-lived way to publish. So the publish job drops `NODE_AUTH_TOKEN` and setup-node's `registry-url` (which exports a placeholder token), keeps `id-token: write` at job level and `--provenance`, guards npm ≥ 11.5.1 / Node ≥ 22.14.0 (the docs' minimums; `.nvmrc`'s 24.13.0 bundles 11.6.2), and logs per package npm's own OIDC line. `scripts/trusted-publishing-lock.test.ts` holds it. Disallowing tokens on npmjs.com is the owner's, and optional
