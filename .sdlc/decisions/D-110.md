**The workflow unblocks itself.** `changesets-pr.yml` now prefers a GitHub App installation token (`vars.RELEASE_APP_ID` + `secrets.RELEASE_APP_PRIVATE_KEY`), then `RELEASE_BOT_PAT`, and only then `GITHUB_TOKEN` — and on that fallback it warns loudly, dispatches every workflow that reports a required check on `changeset-release/main`, waits for each run, and posts its real result as a commit status on the head SHA. Dispatch alone would not do: GitHub documents that check runs from a `workflow_dispatch` run do not satisfy a required status check, while a status with the required context does when no app is pinned (`app_id: null`, as `main` is). It then merges the PR itself and dispatches `quality.yml`, `quality-full.yml` and `release.yml` on `main`, because a GITHUB_TOKEN merge raises no push runs — #393 auto-merged as 54432b9 and nothing released it. `release.yml` publishes only once `Quality Gate` and `Quality (Full) Gate` pass on the commit. The close-and-reopen default of D-094 is retired; setting the App credential (GAPS C5) retires the fallback.
