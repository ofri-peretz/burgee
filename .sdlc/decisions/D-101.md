**Reversed, on the number D-093 said it did not have.** D-093 declined the split because it moved `burgee ÷ cac` from 2.03 to "roughly 1.94" — 5% of a ratio that has to halve — and called it not worth a major. Measured with the corrected instrument (D-100) it is not 5%: the barrel was keeping `help.ts`, `mcp.ts`, `schema.ts`, `plugin.ts`, `manifest.ts` and `seniority/precedence` live for every consumer, and dropping the value half takes the initial load **44,663 → 28,637 bundled bytes** (−36%), the on-disk static graph **60,823 → 42,223**, the modules Node loads for `import 'burgee'` from **22 to 17**, and cold start **2.113 → 1.683**. Against the pre-#415 published figures that is 57,880 → 28,637 and 2.567 → 1.683. The earlier estimate was small because it measured dropping three modules against an instrument that was inlining the other two anyway. Breaking, narrowly: every moved value has a subpath (`burgee/help`, `burgee/mcp`, `burgee/schema`, `burgee/plugin`, `burgee/config`) and **every `type` stayed**, so a typed program that called none of the moved functions needs no change
