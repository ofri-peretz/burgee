**It does not need the owner, and saying it did was the error.** `control-bands.yml` runs weekly, records every series, evaluates Western Electric rules and opens a **Stage 1 intent PR** on a 2σ breach — the policy is already built. What made it look dead: on 2026-09-21 the watcher reported `core-bundled-bytes: 2σ (latest 40562)` while the tree measures **58,027**, and 16 of 19 series had no point from the newest results document. Both facts are innocent. The complete four-axis run is `bench.yml`'s **Tuesday** cron; every other document in `benchmarks/results/` is a partial run from a pull request that writes `{"status":"not-run","reason":"not selected by --axis"}` for the axes it skipped, and the collector reads `<id>.value` off it, finds nothing and moves on. So 40562 is not stale data — it is the newest *complete* measurement, taken before the ~17.5 KB the gate is red about. **The gap was a sentence, not a mechanism:** `latest 40562` reads as *now* and means *last Tuesday*. `unmeasured()` now prints, beside every band, which document failed to measure it and what the band is scoring instead. It is deliberately **not** a gate — a partial run leaves most bands dark and failing on that would fail on every PR, which is how a check earns the reputation that makes the next real red go unread. The B4 breach routes itself at the next complete run
