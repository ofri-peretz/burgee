**Each token takes the ANSI hue its default names — `error` red, `warn` yellow, `ok` green, `flag` cyan, `value` magenta — and `ground` the background; `hint`, `command`, `heading` and `muted` are not imported; and a scheme that does not read is refused with an `ImportError` (`E_IMPORT_CONTRAST`) naming the slot, carrying the unchecked theme.** For Base16 that is the base16-shell assignment read backwards (`base08`, `base0A`, `base0B`, `base0C`, `base0E`, `base00`), for iTerm `Ansi 1`, `3`, `2`, `6`, `5`, `Background Color`; both are exported as data (`BASE16_SLOTS`, `ITERM_SLOTS`). **Why the four stay out:** `hint`, `command` and `heading` default to attributes (`dim`, `bold`, `bold underline`) that a hex would replace rather than colour; `muted` defaults to the terminal's grey, and the matching slot is a scheme's comment grey, built to recede — `base03` 2.50:1 in Default Dark, 2.52:1 in Gruvbox dark hard, Dracula's `Ansi 8` 3.03:1 — so importing it would refuse three well-made schemes over the least-read token. Left at their defaults all four follow the terminal, which in a terminal themed with the same scheme is the scheme's own colour. **Why refuse rather than adjust:** the check is `audit()`, the one `fly()` filters, so whatever an importer returns `fly()` accepts and the two can never disagree; lifting a failing colour until it passes would ship a colour the scheme's author did not choose. The cost is measured and stated: Tomorrow Night's red is 4.46:1 on its ground and is refused. **Parsing:** only what the formats need. Base16: the `baseXX:` lines at any indent (both layouts), JSON text, or a parsed object; a slot written twice, an unquoted `#` value (null to every YAML reader) and a non-hex value are refused. iTerm: the XML plist's colour dicts; a binary plist (with the `plutil` command), a key not followed by its dict, a component outside 0–1, and Display P3 (which read as sRGB would shift every ratio) are refused. Every refusal has a `code` and a `fix`, `PluginError`'s shape.
