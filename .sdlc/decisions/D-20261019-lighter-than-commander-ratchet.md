**`lighter-than-commander` in `.sdlc/bands/claim-ratchets.json` moves from 1.565 to 1.42.** This
is `commander-front-end-diet` R4's last step. The spec left the claim ratchet to "the first commit
after the Benchmarks workflow publishes a CI reading of this build".

**Evidence.** Every CI reading since `2026-10-13-ba91416-ci` gives `burgee/commander` as
**55,346 B** and the ratio as **1.416**. That includes the newest, `2026-10-19-c05c86e-ci`. A
clean local build of main at `6b90ffe` reads the same 55,346 B over commander's 39,084 B.

**The rule.** This is the row's own `derive` rule, the one D-157 set, and `npm run ratchets:propose`
prints it: (55,346 + 80 B CI margin) / 39,084 = 1.418, rounded up to the next 0.005, is **1.42**. That
holds 55,499 B, which is 148 B above the 55,351 B this branch reads after merging #1139. B4's byte ceiling for `burgee/commander` (55,400 B)
still binds before the ratio does.

**What it changes in public.** The claim text in `benchmarks/claims.ts` reads the ceiling, so
`--check` and the README row now say 1.42×. The README's ratchet table and
`apps/docs/content/docs/vs/commander.mdx` were edited to match. `apps/docs/content/docs/benchmarks.mdx`
is generated by `npm run bench:page` from a recorded run, and picks up 1.42× at its next generation.

**The `OVER_INCUMBENT` rows in `scripts/subpath-weight-lock.test.ts`.** These are the same
ratchet in bytes, read off the generated `/docs/weight` page. `burgee/commander` and
`burgee/commander/extra-typings` go from 55,661 to **55,653**, and `burgee/commander/v14` from
55,997 to **56,002**. Main's committed page was generated at `a9356d410b` and read 55,648 / 55,997.
#1139 (merged 2026-10-19, `28843a5`) added 5 B to all three commander entries, from its changes to
shared core files, and did not regenerate the page. The rows could not see the growth, so v14 sat
5 B over its ratchet on main without a red check. This PR regenerates the page, so v14's row moves
up by those 5 B, attributed here. The other two rows still come down 8 B. The page is checked for
rows but not for freshness. That is the gap #1139 slipped through.

**Reversal path.** None by editing. The history is append-only, and
`scripts/claim-ratchets-lock.test.ts` refuses a raise unless it cites a newer decision. A façade
change that needs more than 148 B over commander has to write that decision.
