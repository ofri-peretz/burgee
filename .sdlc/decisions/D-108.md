**The design stands, and the bill is written down rather than absorbed.** `scripts/plugin-schema-lock.test.ts` holds one `schema.json` byte-identical across every package with a `src/plugin.ts`, authored in flagstaff and copied by `schema-sync.mjs`. That is what makes *one contract* true: a plugin author validates against one file, and the same object registers into any subset of the family that is installed. Making `linegauge` the ninth host added three schema definitions — `widthRange`, `widthOverride`, `widths` — and the schema went **9,714 → 11,629 bytes in source, about 1.3 KB minified into `dist/`**. Every host that *imports* it to validate against pays that, for a definition only linegauge reads: five flagstaff budgets moved, two paratext budgets moved, and six of the seven foundation layers' recorded pack weights moved with them. Nothing here is flagstaff's or paratext's code getting bigger. **Not changed, and the alternatives are why.** Per-host schemas would end byte-identity, which is the property the lock exists for and the reason a plugin written for one host is legible to the next. A schema reference to a hosted URL would put a network fetch inside `check`. **Fragments were the answer, and the first CI run is what forced the question.** paratext's default import went 11,122 → **12,465** bytes, a ratio of 2.865 against `ansi-escapes`, for a definition it never reads — it only ever read the capability definition, 2,121 of 8,141 minified bytes. Raising its budgets to absorb that was tried first and was the wrong answer. `scripts/schema-sync.mjs` now also writes per-host *fragments* — exactly the definition a host validates against — and `plugin-schema-lock.test.ts` asserts each deep-equals its source definition, so there are still not two copies free to disagree. paratext imports the fragment and ships the full contract as data it does not import: **6,736 bytes, ratio 1.548** — lighter than it was before linegauge's definitions existed, and the largest single fall any foundation row has had. The published `schema.json` is still one byte-identical file. Rough rule from the two data points: **a new host costs the other eight about 150 bytes per definition each**
