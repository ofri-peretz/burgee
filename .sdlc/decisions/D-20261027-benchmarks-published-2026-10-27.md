a byte-for-byte copy of the CI observation `2026-10-27-ac7ccbc-ci.json` from `bench.yml` run
[40499538893](https://github.com/ofri-peretz/burgee/actions/runs/40499538893) (attempt 1, job
122173463667, artifact `bench-results`).** `ac7ccbc` is GitHub's merge of PR #1294's first commit
(`8222968`) into `main` at `ab33b6f`, so it measured `main` plus the three spawn-delta rows of
[D-20261027-linegauge-closeout-spawn-bars](./D-20261027-linegauge-closeout-spawn-bars.md) and nothing
else. `external-floor` keeps its 2026-10-19 measurement: nothing in it is stale.

**Why a person chooses, and why this run.** The cli-benchmarks spec § *Amended 2026-09-09* makes a
published figure a choice, because a millisecond is a property of the runner
(`benchmarks/published.ts`). The choice has three constraints, and this run is the first that meets
all of them:

1. **The same machine as the page it replaces.** A GitHub Actions runner, AMD EPYC 7763, 4 cores,
   Node 24.13.0, as `2026-10-19.json` was. Publishing a laptop run would move every millisecond row
   for a reason that is not the code, the harm `published.ts` was written against.
2. **Every axis measured.** `perf`, `compat`, `weight`, `reliability` and `runtime` all read
   `measured`. `resultsName` only publishes a complete document.
3. **Every row the open umbrellas wait on.** No CI observation on `main` has the linegauge and
   closeout spawn rows, because they land in this PR. The newest `main` observation
   (`2026-10-26-bc57a47-ci.json`) has seniority's rows and closeout's weights and would leave two of
   the three umbrellas open. A run of this PR's merge ref has all of them.
