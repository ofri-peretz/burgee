# Intent — `apicontract gen` and `extract` run for real: config, plugin loading, safe writes

> Opened from the 2026-11-18 program ([`../apicontract/program.md`](../apicontract/program.md)).
> On `main` at `6aa9d858` the TypeScript generator, the OpenAPI reader and the plugin host exist,
> and `apicontract gen` still throws "not implemented yet". Every generator lane below needs a
> command that loads it, runs it and writes its files the same way.

## What is wanted

`npx apicontract gen` in a repository with an `openapi.yaml` and an `apicontract.config.json` writes
every configured target, and running it twice changes nothing. The writing rules live in one place:

- a `generated` file is rewritten on every run and carries a header that says so and names the
  command that regenerates it;
- a `user` file is written once and never touched again;
- `--check` exits 1 and prints which files are stale, without writing (R-PL3);
- `--dry-run` prints the diff it would write;
- a hand edit inside a generated file is refused with a `fix:` line, not overwritten (R-BL2);
- each run writes `apicontract.map.json`: operation id → the files and symbols generated for it
  (R-BL1), which `check`, `diff` and the contract-test plugins read.

`extract` gets the same loading and writing, with the spec as its one output file.

## Why now

The generators are the product (D-20261112-apicontract-is-a-generator) and eight lanes in Wave 6
produce `Generator` objects. Without a shared runner each would grow its own file writing, and
regeneration safety (vision row 3, metric N1) would be eight implementations instead of one.

## Affected users and systems

`packages/apicontract` (`src/run-*.ts`, `src/cli.ts`, `src/host.ts`). Every
plugin lane consumes its API but does not edit it.

## Constraints

- No new runtime dependency (G4). YAML is read with the parser the OpenAPI reader already uses.
- The config is data: `apicontract.config.json`, or `.mjs`/`.ts` exporting the same object; the JSON
  form validates against a published JSON Schema (`--schema`), so an agent can write it unaided.
- Plugins load only from the config's `plugins` list (R-EX7). No scanning `node_modules`.
- Output is byte-deterministic: same inputs, same bytes, on every OS (line endings `\n`, sorted maps).

## Success criteria

- `gen` on `src/__fixtures__/id.openapi.yaml` with the types target writes the files the generator's
  `sample` declares; a second run reports `0 changed`. Test: `src/run-*.tsgen.test.ts`.
- `gen --check` exits 1 after the spec changes and 0 after `gen`; the exit codes match R-A2.
- Regenerating after a spec change edits zero bytes of any `user` file (N1 = 0), proven by a test
  that edits a user file, changes the spec and regenerates.
- A hand edit inside a `generated` file makes `gen` exit 1 with `fix: move the change to a user file,
  or pass --force`.
- `apicontract gen --json --dry-run` validates against burgee's envelope (A2 = 100%).
- Coverage of `src/run-*.ts` 100%; mutation floor set at first reading (R-M1).

## Defaults taken

- Config file name `apicontract.config.json` (and `.mjs`, `.ts`); the first found wins, in that order.
- The generated header is one line comment in the target language: `// generated by apicontract — do
  not edit; run \`apicontract gen\``. Its hash of the body is what detects a hand edit.
- `--force` exists and overwrites a hand-edited generated file; nothing else ever does.
