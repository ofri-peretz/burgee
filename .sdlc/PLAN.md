# Burgee — the execution plan across every layer

**What this is.** One file an autopilot can run top to bottom. Every step is small enough for
one iteration, names the files it touches, and ends with the command whose output proves it
done. Steps are ordered by dependency; within a wave they are independent and can run in
parallel. Regenerate the tables from the tree, never by hand — step 0.2 makes that a lock.

**What burgee is.** A platform for building CLIs that are AI-friendly, dependency-free and
drop-in for the incumbents they replace. Nine packages in one repository, in four tiers, each
extendable through one plugin object (PRINCIPLES rule 14). `agent-native-cli-layer` is the
legacy slug for the engine's intent; step 0.1 renames it.

## Order of execution for autopilot

Wave 0 first, whole. Then waves 1 and 2 interleaved *per package* — a package's host key and its suites land together, in the order paratext → caique → seniority → closeout → linegauge → bellpull. Wave 3 follows each package's wave-2 completion. Wave 4 runs after wave 2 (it needs the baseline to know what "covered" means). Wave 5 last.

**Stop conditions for an iteration:** a lock goes red on `main` · a step's "done when" command cannot be made true without changing a published claim · a step needs a human (0.3, 5.3, and any Design→Build gate for a package whose design is at `draft`).
