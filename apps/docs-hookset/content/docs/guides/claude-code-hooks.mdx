A rule an agent can break with one command is a check, not a sentence. The git hooks stop a
bad commit; the Claude Code hooks stop an agent from getting around them. `hookset init
--claude` puts four of them, a verify skill to fill in, and a code graph server into a repository:

```text title="npx hookset init --claude"
wrote lefthook.yml, .claude/hooks/guard-bash.mjs, .claude/hooks/stop-after-3.mjs, .claude/hooks/verify-before-stop.mjs, .claude/hooks/codegraph.mjs, .claude/hooks/worktree-sweep.mjs, .claude/settings.json, .mcp.json, .gitignore
```

- **`.claude/hooks/guard-bash.mjs`**, **`stop-after-3.mjs`**, **`verify-before-stop.mjs`**, **`codegraph.mjs`** and **`worktree-sweep.mjs`** are copied
  byte for byte from the package. `hookset check` fails when one differs (`claude-drift`): change
  the canonical copy in burgee, never the vendored one.
- **`.claude/hookset.json`** is the repository's own list of what to ask about and what not to
  edit. `init` writes `{ "ask": [], "frozen": [] }` only when the file is missing, and never
  overwrites it. This repository already had one (it is shown below), so `init` left it alone.
- **`.claude/skills/verify/SKILL.md`** is written once from a template and is the repository's
  to fill in. This repository had already filled its in ([below](#the-verify-skill)), so `init`
  left it alone too.
- **`.claude/settings.json`** gains eight hook entries, enables the `codegraph` server and allows its `codegraph_explore` tool. Any settings already there are kept, and
  an entry that is already wired is not added twice.
- **`.mcp.json`** runs the [CodeGraph](https://github.com/colbymchenry/codegraph) MCP server at
  the version hookset pins, and **`.gitignore`** gains `.codegraph/`, the index it reads. See
  [codegraph](#codegraph).

## What settings.json runs

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard-bash.mjs\"" }] },
      { "matcher": "Edit|Write|MultiEdit|NotebookEdit", "hooks": [{ "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard-bash.mjs\"" }] }
    ],
    "PostToolUse": [
      { "matcher": "Bash", "hooks": [
        { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/stop-after-3.mjs\"" },
        { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/verify-before-stop.mjs\"" }
      ] }
    ],
    "PostToolUseFailure": [
      { "matcher": "Bash", "hooks": [
        { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/stop-after-3.mjs\"" },
        { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/verify-before-stop.mjs\"" }
      ] }
    ],
    "Stop": [
      { "matcher": "", "hooks": [{ "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/verify-before-stop.mjs\"" }] }
    ]
  }
}
```

`init` writes each entry on lines of its own; this is the same content, folded.
`hookset check` fails when one is missing (`claude-unwired`).

## guard-bash

guard-bash reads the tool call Claude Code is about to make on stdin and prints a decision, or
nothing. It reads a command as words, not as a pattern over the raw text, so a commit message or
a heredoc that mentions `--no-verify` is data, not a match.

| Rule | Decision | What it catches |
| :-- | :-- | :-- |
| `no-verify` | deny | `--no-verify`, `git commit -n`, `LEFTHOOK=0` or `HUSKY=0` before a commit or push |
| `hooks-path` | deny | `git config core.hooksPath …`, `git -c core.hooksPath=…` |
| `ci-poll-loop` | deny | an `until` or `while` loop that runs `gh` and `sleep`; it names `gh pr checks <PR> --watch` instead |
| `hooked-timeout` | deny | a foreground `git commit` or `git push` with a timeout under 5 minutes; their hooks outlive it |
| `commit-message` | deny | a `git commit -m` or `-F` whose message the repo's `commit-msg` hook would reject: commitlint with the repo's own config, and a missing `Verified-by:` receipt where the repo runs the provedone station. It names the fix in under a second, before `pre-commit` has run the tests |
| `publish` | ask | `npm publish`, `pnpm publish`, `yarn npm publish`, `changeset publish`, also with options before `publish` |
| `repo-ask` | ask | a phrase the repository lists under `ask` in `.claude/hookset.json` |
| `frozen`, `generated` | deny | an Edit or Write on a listed path ([Generated files](/docs/guides/generated-files)) |

Here a repository asks before its deploy:

```json title=".claude/hookset.json"
{
  "ask": ["npm run deploy"],
  "frozen": []
}
```

And this script sends guard-bash four tool calls the way Claude Code does, one at a time:

```js title="ask-guard.mjs"
import { spawnSync } from 'node:child_process';

const calls = [
  { tool_name: 'Bash', tool_input: { command: 'git push --no-verify' } },
  { tool_name: 'Bash', tool_input: { command: 'git commit -m "docs: never use --no-verify\n\nVerified-by: none (docs example)"', timeout: 600000 } },
  { tool_name: 'Bash', tool_input: { command: 'git push' } },
  { tool_name: 'Bash', tool_input: { command: 'npm run deploy' } },
];
const env = { ...process.env, CLAUDE_PROJECT_DIR: process.cwd() };
for (const call of calls) {
  const r = spawnSync(process.execPath, ['.claude/hooks/guard-bash.mjs'], { input: JSON.stringify(call), encoding: 'utf8', env });
  const out = r.stdout ? JSON.parse(r.stdout).hookSpecificOutput : undefined;
  console.log(out ? `${out.permissionDecision}: ${out.permissionDecisionReason}` : 'no opinion: the call runs');
}
```

```text title="node ask-guard.mjs"
deny: [guard-bash:no-verify] Git hooks are this repo's gate: never skip them (--no-verify, commit -n, LEFTHOOK=0). If a hook fails, fix what it reports. If it is slow, wait: commit/push hooks can take 3–4 minutes, and a killed push may still have landed (check `git log origin/<branch> -1` before retrying).
no opinion: the call runs
deny: [guard-bash:hooked-timeout] `git push` runs this repo's pre-push hooks, which take minutes: not a hang. Run it again with `timeout: 600000` (or `run_in_background: true`) and wait for it. If an earlier push was killed, check `git log origin/<branch> -1` first: it may have landed.
ask: [guard-bash:repo-ask] This repo lists `npm run deploy` in .claude/hookset.json as a step a person approves: it overwrites or ships something that is hard to take back.
```

The second call mentions `--no-verify` only inside its message, and runs with a long timeout,
so guard-bash has no opinion. The third is a push on Claude Code's default timeout, which the
pre-push hook would outlive.

The file carries its own cases. `--self-test` runs them:

```text title="node .claude/hooks/guard-bash.mjs --self-test"
ok: 34 denied, 23 allowed, 24 asked, 10 timed, 5 edits, 13 messages
```

## stop-after-3

"After three failed tries, stop and ask" can be written in a CLAUDE.md, and an agent can read
past it. stop-after-3 counts failed test runs per session after every Bash call: a passing run
resets the count, and the third failure in a row ends the turn (`continue: false`) with a
message telling the agent to show the person what fails, what it tried, and the options.

A test run is a command whose first word, past `npx`, `pnpm exec` and the like, is a test
runner: `vitest`, `jest`, `mocha`, `pytest`, `ava`, `tap`, `npm test`, `npm run test*`,
`npm run ci:local`, `turbo run test`, `node --test`, `cargo test`, `go test` or
`playwright test`. `echo npm test` runs echo, and does not count. An interrupted run leaves the
count where it was. The count lives in a file under the system's temporary directory.

```text title="node .claude/hooks/stop-after-3.mjs --self-test"
ok: 9 counted, 7 ignored, stop on 3
```

## verify-before-stop

"Run the tests before you say you're done" is the other sentence an agent reads past. A whole
suite inside a Stop hook would hold every turn for minutes, so verify-before-stop asks for the
run instead of making it. After a test run passes (the same test runs stop-after-3 counts), it
records a fingerprint of the uncommitted code. Only a run whose exit status is the tests' own
counts: a foreground command with the test last and no `|`, `||`, `;` or `&` that could hide a
failure or edit code after it, so `npm test || true` and `npx vitest run | tail` prove nothing. When the turn ends while uncommitted code differs
from that fingerprint, or no run passed this session, it sends the turn back once
(`decision: "block"`) naming the changed files. The second stop of the same turn
(`stop_hook_active`) always ends it, so an agent that has to ask a question first is never stuck.

It judges only code this session changed: a path its Edit or Write tools wrote, or one whose
content changed across one of its own Bash calls. A file another session or a generator rewrites
in the same checkout does not send this session's turn back.

Committed work is the commit and push hooks' to judge. `.md`, `.mdx` and `.txt` files do not
count, and neither do the globs a repository lists under `verifyIgnore` in `.claude/hookset.json`.

```text title="node .claude/hooks/verify-before-stop.mjs --self-test"
ok: 19 cases
```

## The verify skill

The most useful check is running the change the way a user would. `init --claude` writes
`.claude/skills/verify/SKILL.md` from a template once, and never overwrites it: how to boot the
app or CLI, how to drive it and read back what it shows, and a feature map (each feature, how to
reach it, what working means). `hookset check` fails while the file is missing
(`verify-skill-missing`), still has a `TODO(verify)` line (`verify-skill-unfilled`), or has lost
`name: verify` or `## Feature map` (`verify-skill-incomplete`). This repository's, filled in:

```md title=".claude/skills/verify/SKILL.md"
---
name: verify
description: Run the CLI as a user would and read back its exit code and output. Use before committing a behaviour change.
---
```

## check sees the pack

Once `.claude/hookset.json` exists, `hookset check` also checks the pack:

```text title="npx hookset check"
hookset: ok (hookset@1.0.0)
! the mutation station is not declared yet (optional)
  fix: add "hook:mutation" to package.json scripts when the repo has it: changed-lines mutation testing
! the test-integrity station is not declared yet (observe)
  fix: add "hook:test-integrity" to package.json scripts when the repo has it: no .only, .skip or weakened assertion in the diff
! the proofline station is not declared yet (observe)
  fix: add "hook:proofline" to package.json scripts when the repo has it: the change carries its Checked line
! the triggerlist station is not declared yet (observe)
  fix: add "hook:triggerlist" to package.json scripts when the repo has it: protected paths changed only with their trigger
```

A repository with a `.claude/` directory and no `.claude/hookset.json` gets a
`claude-not-adopted` warning, so the pack reaches every repository where an agent works.

## codegraph

The `codegraph` MCP server answers "where is this symbol, what calls it, how does A reach B" from
a prebuilt symbol graph in one `codegraph_explore` call, where grep takes a search, a read and a
search again. The server reads an index under `.codegraph/` and never builds one, and a cloud
session starts from a fresh clone without it. `codegraph.mjs` runs on `SessionStart` and starts
`codegraph init` in the background (`codegraph sync` when the index is there), so the session is
not held for it; the server picks the index up when it lands.

It does nothing in a repository whose `.mcp.json` runs no `codegraph` server, or with
`HOOKSET_CODEGRAPH=0`. `hookset check` fails when `.mcp.json` does not run the server as hookset
pins it (`codegraph-mcp-missing`, `codegraph-mcp-drift`), `.gitignore` does not list `.codegraph/`
(`codegraph-not-ignored`) or settings.json does not enable it (`codegraph-mcp-disabled`).

Why it is in the pack, measured on burgee: on tasks that trace a flow through the code it cut
greps from 29 to 18 and file reads from 24 to 3. The numbers, the tasks and how to run them again
are in [`packages/hookset/scripts/codegraph-bench`](https://github.com/ofri-peretz/burgee/tree/main/packages/hookset/scripts/codegraph-bench).

## worktree-sweep

Claude Code's `--worktree` and isolated subagents make a full checkout per task and never remove
it. `worktree-sweep.mjs` runs on `SessionStart`, at most once a day per clone, and starts
`hookset worktrees --prune` in the background, so the session is not held for it. The sweep
removes only a linked worktree that is clean, unlocked, fully pushed and unchanged for 3 days,
with `git worktree remove` and never `--force`; `git worktree lock` keeps one. Its last report is
in a `.log` file beside the day stamp under the system temporary directory.

`HOOKSET_WORKTREES=0` turns it off; `HOOKSET_WORKTREES_OLDER_THAN=<days>` changes the age.
