The shortcuts truepass reports are the ones an agent takes when it is told to make a red suite
green. So the findings are written for the agent as much as for a person: each one says what is
wrong, why it matters, and the fix, in one message.

## Every message ends in a fix

Both halves use one format: `<issue>: <why it matters>. fix: <what to do>`. An agent that reads a
lint finding or a `truepass diff` finding has the instruction in the same line, without opening
these docs:

```text
Test retry: Retries turn an intermittent failure into a pass, hiding the flakiness the test exists to report. fix: remove the retry and fix the cause of the flake (a race, shared state, a fixed sleep, an unmocked clock or network). If the retry is a deliberate policy, cite the decision id (D-…) or issue URL in a comment on this line or the line above
```

## --json

`truepass diff --json` prints one envelope on stdout: `ok`, `data.base`, `data.findings` (each
with `check`, `path`, `line` and `message`) and `data.exitCode`. [GitHub
Actions](/docs/recipes/github-actions#the-envelope) shows a real one.

A usage error goes to stderr as text, then as one JSON line, `{"error":{"kind","code","message"}}`,
whenever stderr is not a terminal. An agent that runs the command through a pipe gets the error
as data even without `--json`.

## An MCP server

`truepass --mcp` serves the program over the Model Context Protocol, from the same declaration.
`diff` is declared with `effects: "read_only"`, as the schema above shows, so a client can tell it
changes nothing.

## Exit codes are the contract

| Exit | Meaning                                                                         |
| ---: | :------------------------------------------------------------------------------ |
|    0 | no findings                                                                     |
|    1 | a finding; read the message                                                     |
|    2 | a usage error, such as a base this checkout does not have, with the fetch to run |

These, the `--json` shape, the four rules and `truepass diff` are truepass's 1.0 contract: a
change to any of them waits for a 2.0 ([the changelog](/docs/changelog)).

## In an agent's instructions

A line in the repository's agent instructions is enough to close the loop:

```md
- Never add `.only`, an unexplained skip, a fixed sleep or a retry to make a test pass;
  `truepass/eslint` reports them.
- A weakened assertion or a snapshot update needs an `Assertion: <why>` or `Snapshot: <why>`
  line in the commit message; `truepass diff` runs on pre-push.
```
