**burgee** is a CLI framework that **replaces commander and yargs**, is drop-in compatible
with both, and serves every command through every format a caller wants. You declare a
command once; help, `--json`, `--schema`, an MCP server and shell completions are all read
from that one declaration, so none of them can drift from the others.

```text
defineCommand()  ──▶  manifest  ──┬──▶  human help
                                  ├──▶  --json      one stable envelope
                                  ├──▶  --schema    versioned, one document per surface
                                  ├──▶  --mcp       an MCP server, generated
                                  ├──▶  completions bash · zsh · fish · pwsh
                                  ├──▶  TypeScript types
                                  └──▶  docs + llms.txt
```

## Built for the CLIs agents drive

An agent calling a CLI through a shell pays in calls, tokens and misreads. A burgee
command declares itself once and an agent reads that declaration directly: a stable
`{ ok, data }` envelope under `--json`, a versioned schema under `--schema`, the same
commands as MCP tools under `--mcp`, and an exit code that says *rewrite the command* (`2`)
rather than *something went wrong*. [Your CLI is an agent tool](/docs/agent-surfaces) has
each surface.

## Already on commander or yargs?

Change one import:

```diff
- import { Command } from 'commander';
+ import { Command } from 'burgee/commander';
```

Compatibility is graded, not asserted: each host's own test suite runs against burgee in
CI. The rates are on [Compatibility](/docs/compatibility), and the migration is on
[burgee vs commander](/docs/vs/commander) and [burgee vs yargs](/docs/vs/yargs).
